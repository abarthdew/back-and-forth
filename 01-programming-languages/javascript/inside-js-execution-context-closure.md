## 실행 컨텍스트 개념

- **콜 스택**: 함수를 호출할 때마다 호출 정보가 쌓이는 스택. 실행 컨텍스트는 콜 스택에 들어가는 실행 정보 하나에 해당한다.
- ECMAScript는 실행 컨텍스트를 "실행 가능한 코드 블록이 실행되는 환경"으로 정의한다. 대부분의 경우 이 "코드 블록"은 **함수**다.
- 실행 컨텍스트가 형성되는 3가지 경우: 전역 코드, `eval()` 실행, 함수 안의 코드 실행.
- 새 컨텍스트가 생성되면 스택에 쌓이고, 제일 위(가장 최근에 쌓인 것)가 현재 실행 중인 컨텍스트다.

## 실행 컨텍스트 생성 과정

```javascript
function execute(param1, param2) {
  var a = 1, b = 2;
  function func() { return a + b; }
  return param1 + param2 + func();
}
execute(3, 4);
```

1. **활성 객체(변수 객체) 생성**: 매개변수·지역 변수·내부 함수를 저장할 객체를 만든다.
2. **arguments 객체 생성**: 활성 객체가 `arguments` 프로퍼티로 이를 참조.
3. **스코프 정보 생성**: 현재 컨텍스트의 유효 범위(스코프 체인)를 연결 리스트 형태로 구성. 생성된 활성 객체가 스코프 체인의 맨 앞에 추가된다.
4. **변수 생성**: 지역 변수·내부 함수가 변수 객체(=활성 객체) 안에 생성된다. 이 시점에는 `undefined`로만 초기화되고, 실제 값 대입은 표현식이 실행되는 시점에 이뤄진다(→ 호이스팅의 원인).
5. **this 바인딩**: 참조할 객체가 없으면 전역 객체를 참조.
6. **코드 실행**: 변수 객체 생성이 끝난 뒤에야 실제 표현식들이 순서대로 실행된다.

## 전역 실행 컨텍스트의 특수성

- `arguments` 객체가 없고, 전역 객체 하나만을 포함하는 스코프 체인을 가진다.
- 전역 실행 컨텍스트의 변수 객체가 곧 **전역 객체 자체**이므로, 전역에서 선언한 함수/변수가 전역 객체의 프로퍼티가 된다.
- 브라우저에서는 최상위 코드가 곧 전역 코드지만, **Node.js에서는 다르다** — 파일 하나가 하나의 모듈로 동작해 `var`로 선언한 최상위 변수는 모듈의 지역 변수가 된다. `var` 없이 값을 대입하면 전역 객체(`global`)를 오염시키므로 주의가 필요.

## 스코프 체인

- 자바스크립트는 블록({ }) 단위가 아니라 **함수** 단위로만 유효 범위를 가진다(C 계열 언어와 달리 `if`/`for` 블록은 스코프를 만들지 않음).
- 각 함수는 `[[scope]]` 프로퍼티로 자신이 생성된 시점의 스코프 체인을 참조한다. 함수가 실행되면, 그 함수의 `[[scope]]`를 복사한 뒤 새로 생성된 변수 객체를 맨 앞에 추가해 새로운 스코프 체인을 만든다.
- 요약: **스코프 체인 = 현재 실행 컨텍스트의 변수 객체 + 상위 컨텍스트의 스코프 체인**.
- 식별자를 찾을 때는 스코프 체인의 첫 번째 객체부터 시작해 대응하는 프로퍼티를 찾을 때까지 상위로 올라간다. (`this`는 식별자가 아니라 키워드라서 스코프 체인 참조 없이 접근 가능.)

## with 키워드

```javascript
var y = {x: 5};
function withExamFunc() {
  var x = 10;
  var z;
  with (y) {
    z = function() { console.log(x); }  // 5 (y 객체의 x)
  }
  z();
}
```
- `with` 블록 실행 동안 지정한 객체가 스코프 체인의 맨 앞(활성 객체 바로 앞)에 추가된다. `eval`과 함께 성능 저하 요인으로 꼽혀 사용을 지양해야 한다.

## 호이스팅

```javascript
foo();          // TypeError: foo is not a function
bar();          // undefined 출력 (x 대입 전에 실행되므로)

var foo = function() { console.log(x); };
function bar() { console.log(x); }
var x = 1;
```
- 함수 생성 과정에서 변수 `foo`, 함수 `bar`, 변수 `x`가 먼저 생성되고(`foo`, `x`는 `undefined`로 초기화), 그 다음에 코드가 순서대로 실행되기 때문에 위와 같은 결과가 나온다 — "선언은 끌어올려지지만 대입은 원래 위치에서 실행된다"는 원리다.

## 클로저

```javascript
function outerFunc() {
  var x = 10;
  var innerFunc = function() { console.log(x); };
  return innerFunc;
}
var inner = outerFunc();
inner();   // 10
```
- `innerFunc`의 `[[scope]]`는 `outerFunc`의 변수 객체를 포함한다. `outerFunc`의 실행이 끝나 컨텍스트는 사라져도, `outerFunc`의 변수 객체는 `innerFunc`의 스코프 체인에 의해 계속 참조되므로 사라지지 않는다 — 이것이 **클로저**다.
- **클로저**: 이미 생명 주기가 끝난 외부 함수의 변수를 참조하는 함수. 이때 클로저가 참조하는 외부 변수(`x`)를 **자유 변수**라 부른다.
- 함수가 일급 객체이기 때문에 가능한 패턴이며, 함수형 언어에서 특히 중요하게 쓰인다.

## 클로저 활용 패턴

1. **정보 캡슐화**: 클로저로 감싼 변수(`buffAr` 등)를 외부에서 직접 건드리지 못하게 하고, 오직 반환된 함수를 통해서만 접근하게 한다.
2. **setTimeout에 인자 전달**: `setTimeout`은 콜백에 인자를 직접 넘길 수 없으므로, 클로저로 감싼 함수를 반환해 원하는 인자에 접근하게 한다.
```javascript
function callLater(obj, a, b) {
  return function() {
    obj['sum'] = a + b;
    console.log(obj['sum']);
  };
}
var sumObj = { sum: 0 };
setTimeout(callLater(sumObj, 1, 2), 500);  // 3
```
3. **함수에 커스텀 로직 연결**: 특정 형식(`function(greeting){}`)의 콜백만 받는 라이브러리에, 클로저로 자유 변수(`obj`, `methodName`, `name` 등)를 바인딩한 새로운 함수를 만들어 전달할 수 있다.

## 클로저 사용 시 주의사항

1. **클로저의 자유 변수는 매번 변할 수 있다** — 클로저를 여러 번 호출하면 자유 변수 값이 호출마다 누적/변경된다(스냅샷이 아님).
2. **하나의 자유 변수를 여러 함수가 공유할 수 있다** — 같은 스코프의 자유 변수를 참조하는 함수가 여럿이면, 한쪽에서 변경한 값이 다른 쪽 호출 결과에도 영향을 준다.
3. **루프 안에서 클로저를 쓸 때 흔한 함정**:
```javascript
function countSeconds(howMany) {
  for (var i = 0; i <= howMany; i++) {
    setTimeout(function() { console.log(i); }, i * 1000);
  }
}
countSeconds(3);
// 의도: 0,1,2,3을 순서대로 출력
// 실제 결과: 4가 4번 출력됨 (setTimeout 콜백이 실행될 때는 이미 루프가 끝나 i가 4)
```
해결책은 즉시 실행 함수(IIFE)로 매 반복마다 새로운 스코프를 만들어 그 시점의 `i` 값을 캡처하는 것:
```javascript
function countSeconds(howMany) {
  for (var i = 0; i <= howMany; i++) {
    (function(currentI) {
      setTimeout(function() { console.log(currentI); }, currentI * 1000);
    }(i));
  }
}
```
(참고: `let`으로 선언하면 블록 스코프가 생겨 이 문제가 자연스럽게 해결되지만, 이 노트는 `var` 시대의 근본 원리를 다룬다.)
