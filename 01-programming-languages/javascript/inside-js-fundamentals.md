## 자바스크립트의 핵심 개념

- 거의 모든 것이 객체다. 예외는 기본 데이터 타입(`boolean`, `number`, `string`, `null`, `undefined`) 뿐이며, 이들도 필요 시 객체처럼 다룰 수 있다.
- 함수도 객체다 — 일반 객체보다 조금 더 많은 기능(호출 가능성)을 가진 객체이며, **일급 객체**로 취급된다.
- 모든 객체는 숨겨진 링크인 프로토타입(`[[Prototype]]`)을 가지며, 이 링크는 해당 객체를 생성한 생성자의 프로토타입 객체를 참조한다.
- 실행 컨텍스트라는 독자적인 과정으로 코드를 실행하며, 이 과정에서 클로저가 구현된다(자세한 내용은 [실행 컨텍스트와 클로저](./inside-js-execution-context-closure.md) 참고).

## 패러다임: 객체지향 & 함수형

- 클래스를 지원하지 않지만, 프로토타입 체인과 클로저로 상속·캡슐화·정보 은닉 같은 객체지향 개념을 구현할 수 있다(자세한 내용은 [객체지향 프로그래밍](./inside-js-oop.md) 참고).
- 일급 객체와 클로저 덕분에 함수형 프로그래밍도 가능하다(자세한 내용은 [함수형 프로그래밍](./inside-js-functional-programming.md) 참고). 단, 과도한 클로저 사용은 가독성을 해칠 수 있다.

## 자바스크립트의 단점

- 유연성과 표현력이 높은 만큼 디버깅이 어려움.
- 느슨한 타입 체크로 컴파일 타임에 오류를 잡지 못하고 런타임 오류로 이어지기 쉬움.
- 최상위 레벨 객체가 모두 전역 객체 안에 위치해 이름 충돌 위험이 있음.
- 1999년 ECMAScript3의 모호한 명세가 원인으로 꼽히며, 2009년 ECMAScript5 이후 지속적으로 개선되고 있음.

## 기본 타입과 참조 타입

값들은 크게 **기본 타입**(숫자, 문자열, 불린, `null`, `undefined`)과 **참조 타입**(그 외 전부 — 배열, 함수 포함)으로 분류된다.

```javascript
var intNum = 10;
var singleQuoteStr = 'single';
var boolVar = true;
var emptyVar;        // undefined
var nullVar = null;

console.log(typeof intNum, typeof singleQuoteStr, typeof boolVar, typeof emptyVar, typeof nullVar);
// number string boolean undefined object
```

- **숫자**: C와 달리 정수/실수 구분이 없고 모든 숫자가 64비트 부동소수점(C의 double과 유사)으로 저장된다. `5/2`는 `2.5`.
- **문자열**: 작은따옴표/큰따옴표로 생성, 불변(immutable). 인덱스로 접근은 가능하지만 `str[0] = 'a'`처럼 재할당은 무시된다.
- **null vs undefined**: `undefined`는 값이 할당되지 않은 상태(타입이자 값), `null`은 개발자가 명시적으로 "비어있음"을 표시하는 값. `typeof null`은 `"object"`이므로 `null` 비교는 `===`로 해야 한다.
- **참조 타입(객체)**: 숫자/문자열/불린/`null`/`undefined`를 제외한 모든 값. key-value로 프로퍼티를 저장하는 컨테이너이며, 프로퍼티 값이 함수면 **메서드**라 부른다.

객체 생성 3가지 방법:
```javascript
var foo = new Object();           // 1. 내장 생성자 함수
foo.name = 'foo';

var bar = { name: 'foo' };        // 2. 객체 리터럴

function Foo(name) { this.name = name; }  // 3. 생성자 함수
var baz = new Foo('foo');
```

프로퍼티 읽기/쓰기는 대괄호(`obj['key']`) 또는 마침표(`obj.key`) 표기법을 쓰며, `for...in`으로 모든 프로퍼티를 순회할 수 있다. `delete obj.name`은 프로퍼티만 지울 뿐 객체 자체는 삭제하지 못한다.

## 참조 타입의 특성

```javascript
var objA = { value: 40 };
var objB = objA;          // 같은 객체를 참조
objB.value = 50;
console.log(objA.value);  // 50 (objA도 바뀜)
```

- 동등 연산자(`==`)로 비교 시 기본 타입은 값을, 참조 타입은 **참조값**을 비교한다.
- 함수 호출 시 기본 타입은 값에 의한 호출(복사 전달)이라 함수 내부에서 바꿔도 원본은 불변이지만, 참조 타입은 참조에 의한 호출이라 함수 내부에서 프로퍼티를 바꾸면 원본 객체도 바뀐다.

## 프로토타입

- 모든 객체는 자신을 생성한 생성자 함수의 `prototype` 프로퍼티가 가리키는 객체를 부모로 하는 `[[Prototype]]` 링크를 가진다.
- 객체 리터럴로 만든 객체의 프로토타입은 `Object.prototype`이다. `foo.toString()`이 에러 없이 동작하는 이유는 `foo` 자신에게 없는 메서드를 프로토타입 체인을 타고 올라가 `Object.prototype`에서 찾기 때문.
- 객체 생성 이후에도 프로토타입 객체를 동적으로 교체할 수 있으며, 이 특성을 이용해 상속을 구현한다.

## 배열

- 크기를 미리 지정할 필요가 없고, 어떤 타입의 값이든 섞어서 저장 가능(`[1, 2, 'red', 4, 5]`).
- `length`는 **가장 큰 인덱스 + 1**을 나타낼 뿐, 실제 원소 개수와 일치하지 않을 수 있다(`arr[100] = 100`만 해도 `length`는 101이 된다). `length`를 줄이면 그 범위를 벗어난 값은 삭제된다.
- 배열도 객체이므로 `delete arr[i]`는 해당 인덱스를 비울 뿐(`empty` 슬롯) 배열을 줄이지 않는다 — 실제로 잘라내려면 `splice()`를 쓴다.
- 배열의 프로토타입은 `Array.prototype`(다시 `Object.prototype`을 부모로 가짐)이라, `push`/`pop` 같은 배열 전용 메서드를 프로토타입 체인을 통해 쓸 수 있다. 일반 객체는 `Array.prototype`을 상속하지 않으므로 `push()`를 호출하면 에러가 난다.
- **유사 배열 객체(array-like object)**: `length` 프로퍼티만 있으면 `Array.prototype.push.apply(obj, [...])`처럼 배열 메서드를 빌려 쓸 수 있다.

## 기본 타입과 표준 메서드

숫자·문자열·불린은 객체가 아니지만 메서드를 호출할 수 있다 — 호출 순간 임시로 래퍼 객체로 변환되어 메서드가 실행된 뒤 다시 기본값으로 돌아간다.
```javascript
var num = 0.5;
console.log(num.toExponential(1));  // "5.0e-1"
console.log("test".charAt(2));      // "s"
```

## 주요 연산자

- `+`: 숫자 덧셈 또는 문자열 연결.
- `typeof`: 피연산자의 타입을 문자열로 반환.
- `==` vs `===`: `==`는 타입이 다르면 타입 변환 후 비교(`1=='1'` → `true`), `===`는 타입까지 정확히 일치해야 `true`(`1==='1'` → `false`, 권장).
- `!!`: 값을 불린으로 강제 변환. `!!0`, `!!''`, `!!null`, `!!undefined`는 `false`이고, `!![1,2,3]`, `!!{}`(빈 객체라도!)는 `true`.
